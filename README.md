# ReturnTag

ReturnTag is a WordPress and WooCommerce-based lost-item recovery platform for
the United States market. Its independent WordPress plugin is named **TagCore**
and lives in `plugin/tagcore`.

The repository contains an executable engineering foundation for a modular
WordPress plugin. WordPress can load the plugin, Composer provides PSR-4 and
runtime infrastructure, Node tooling builds isolated admin/public assets, and
CI enforces the initial quality gates. RT-101 provides the forward-only
Migration runtime; RT-102 through RT-107 register schema versions `1` through
`7` for the batches, tags, batch export audit, authentication challenge,
conversation, message, and access token tables. Product business workflows are
not yet implemented.

## Frozen product baseline

- Supported tag types are exactly `sticker`, `classic_tag`, and `smart_tag`.
- Each physical tag has one public six-character Tag ID, and that same ID is
  used for first activation.
- There is no separate Claim ID or hidden activation code.
- Orders, shipments, tracking numbers, and logistics records are not mapped to
  Tag IDs.
- Tag IDs are generated by production batch, exported to manufacturers, and
  never reused after generation or export.
- Smart finding networks and ReturnTag QR recovery are independent systems.
- Phase one does not read Apple or Google account, device, pairing, or location
  data.
- WordPress table names must use `$wpdb->prefix`; `wp_` is never hard-coded.

The complete product requirements are in [docs/PRD.md](docs/PRD.md).

## Engineering baseline

```text
Runtime       PHP 8.3+ (8.4 production), WordPress 6.9+, current WooCommerce
Backend       Composer, PSR-4, WordPress APIs, $wpdb repositories, Action Scheduler
Admin         React through WordPress packages, TypeScript, @wordpress/scripts
Public site   PHP SSR, Interactivity API-ready Script Modules, progressive enhancement
Quality       WPCS/PHPCS, PHPCompatibilityWP, PHPStan level 8, PHPUnit 9.6
Infrastructure wp-env, GitHub Actions, Dependabot, Playwright, immutable release ZIP
```

Runtime WordPress packages are pinned to the WordPress 6.9 distribution line
for minimum-version compatibility. WordPress supplies React and related
packages at runtime; they are not bundled into TagCore assets. Admin and public
styles use separate `returntag-` roots and do not use Tailwind or global CSS
resets.

Action Scheduler is available as queue infrastructure, but TagCore does not
schedule business jobs yet. The repository similarly defines no REST route,
email provider, OTP flow, activation flow, finder relay, WooCommerce business
hook, or batch workflow. The only product tables are the RT-102 batches schema,
the RT-103 tags schema, the RT-104 batch export audit schema, the RT-105
authentication challenge schema, the RT-106 conversation and message schemas,
and the RT-107 access token schema.

RT-007 defines the four approved global feature flag names and a read-only
WordPress option adapter. Missing or ambiguous values fail closed, and no
option is created automatically. No product workflow consumes these controls
yet, so changing an option does not currently enable product behavior.

RT-008 adds a PSR-3 application logging contract, a defensive context
sanitizer, and a single-line structured WordPress error-log adapter. The
adapter is disabled by default and is not registered by the plugin bootstrap;
no product workflow or business audit event is logged yet.

RT-101 adds an ordered, locked, retry-safe Migration Runner and WordPress
lifecycle integration. It runs only during single-site activation, a completed
TagCore upgrade, or an authorized admin compensation check. RT-102 registers
Migration `0001` for `returntag_batches`; RT-103 registers Migration `0002`
for `returntag_tags` and verifies the version `1` batches contract before it
runs. RT-104 registers Migration `0003` for `returntag_batch_exports` after
verifying the complete version `2` predecessor chain. The site-scoped Schema
version advances to `3` only after all three tables pass their postcondition
checks. RT-105 registers Migration `0004` for
`returntag_auth_challenges` after verifying version `3`; it defines encrypted
email, keyed lookup, code-hash, bounded-counter, and expiry storage without
implementing an OTP or Finder verification flow. Schema version advances to
`4` only after all four tables verify. RT-106 registers Migration `0005` for
`returntag_conversations` and Migration `0006` for `returntag_messages`.
Conversation status has no database default and must be supplied explicitly by
future application code; message delivery status defaults to `queued`. Schema
version advances independently through `5` and `6` only after each table
verifies. RT-107 registers Migration `0007` for
`returntag_access_tokens`, storing only a unique case-sensitive token digest and
explicit UTC lifecycle timestamps. It adds no Token generator, secure-link
route, or exchange behavior. Schema version advances to `7` only after the
complete predecessor chain and access token table verify. Normal public
requests do not run DDL.
Network-wide activation is not supported in Milestone 1.

## Requirements

- PHP 8.3 or newer with `curl`, `intl`, `mbstring`, `mysqli` or `pdo_mysql`,
  `openssl`, `sodium`, and `zip` available.
- Composer 2.
- Node.js 24 LTS and npm.
- Docker for `wp-env` and WordPress integration tests.

On Windows, Docker Desktop with WSL2 is recommended. Native PHP remains useful
for fast Composer, lint, static-analysis, and unit-test feedback.

## Setup and validation

Install PHP dependencies from the plugin package directory:

```text
cd plugin/tagcore
composer install
composer check
```

Install and validate the JavaScript toolchain from the repository root:

```text
npm ci
npm run check
```

Start the default or minimum WordPress environment:

```text
npm run env:start
npm run env:start:minimum
```

WordPress 7.0.2 and the security-backported 6.9.5 release are pinned rather
than cloned from floating Git branches. WooCommerce 10.9.4 is the pinned
current test version. The additional
`env:start:woocommerce-9` and `env:start:minimum-woocommerce-9` commands run
ephemeral compatibility environments with WooCommerce 9.9.7. The previous
major is test-only; production must use the current patched WooCommerce line.

With the selected environment running, execute WordPress integration tests and
browser tests:

```text
npm run test:php:integration
npm run test:e2e
```

The minimum environment uses its corresponding integration-test command:

```text
npm run test:php:integration:minimum
```

## Release

Pushing an approved tag named `tagcore-v{version}` runs the release-artifact
workflow. It verifies the tag against the plugin header, installs production
dependencies, builds assets, packages `tagcore/` at the ZIP root, and emits a
SHA-256 checksum. Tagging, committing, pushing, publishing, and deploying
remain explicit human-authorized actions.

No production credentials, manufacturer exports, personal data, plaintext
OTPs, or plaintext access tokens may be committed to this repository.
